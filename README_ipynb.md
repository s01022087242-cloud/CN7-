# 사출성형(CN7) 불량 예측 모델 — 분석 파이프라인

`미니_프로젝트(08_27).ipynb`에서 수행한 불량 예측 모델링 전체 과정과 결과를 정리한 문서입니다.

## 데이터

- **원본 파일:** `labeled_data.csv`
- **크기:** 7,996행 (정상 7,925건 / 불량 71건, 불량 비율 0.9%)
- **대상:** 아반떼 CN7 앞유리 사이드 몰딩 사출성형 공정 데이터

## 전체 분석 파이프라인 흐름도

```
======================================================
             [ 전체 분석 파이프라인 흐름도 ]
======================================================

[STEP 1] 데이터 준비 및 분할
 |
 +-- 1-1. 원본 데이터 (df) 로드
 +-- 1-2. 무의미한 컬럼 제거 (전부 0인 값, ID 등)
 +-- 1-3. 타겟 변수 변환 (Pass/Fail -> 1/0, 불량=1 기준)
 |
 +-- 1-4. Train / Test Split (8:2 비율 분할)
     |
     +-> (A) Train Data (80%) : 2단계 모델 학습용으로 이동
     +-> (B) Test Data  (20%) : 4단계 최종 평가 전까지 봉인 (Data Leakage 방지)



[STEP 2] 전처리 및 모델 학습 (A. Train Data 사용)
 |
 +-- 2-1. 공통 전처리 파이프라인 구성 (수치형: 스케일링 / 범주형: 원핫인코딩)
 |
 +-- 2-2. 4가지 조건으로 모델 병렬 학습 (GridSearchCV, 5-Fold)
     |
     +-> 조건 1: Random Forest (원본 + 클래스 가중치 부여)
     +-> 조건 2: Random Forest (전처리 후 SMOTE 데이터 증강)
     +-> 조건 3: Gradient Boosting (원본 + 클래스 가중치 부여)
     +-> 조건 4: Gradient Boosting (전처리 후 SMOTE 데이터 증강)
     |
     * 목표 지표: 무조건 'Recall(불량 미탐 방지)' 최우선 기준 적용



[STEP 3] 최적 모델 선정
 |
 +-- 3-1. 4개의 완성된 모델 결과 비교
 +-- 3-2. Recall이 가장 높고, Precision 방어가 잘 된 1등 모델(Best Model) 픽업



[STEP 4] 실전 평가 및 임계값 튜닝 (B. Test Data 사용)
 |
 +-- 4-1. 1등 모델에 봉인해뒀던 Test Data(20%) 주입
 +-- 4-2. 데이터별 '불량일 확률(Probability)' 예측
 |
 +-- 4-3. 임계값(Threshold) 시뮬레이션
     |
     +-> Threshold 0.2, 0.3, 0.4 ... 0.8까지 직접 깎아보며
     +-> 미탐(불량 놓침)과 오탐(정상을 불량으로 착각) 비용 비교
 |
 V
[최종 결론] 현장 비즈니스 상황에 맞는 최적의 Threshold 확정
```

## 핵심 설계 포인트 — 데이터 누수 방지

이 파이프라인의 핵심은 **STEP 1에서 Train/Test를 가장 먼저 분리하고, Test를 STEP 4까지 절대 건드리지 않는다**는 점입니다.

- SMOTE는 `sklearn.pipeline.Pipeline`이 아닌 **`imblearn.pipeline.Pipeline`**으로 감싸서, 학습(`.fit()`) 시점에만 적용되도록 구성했습니다. 이렇게 하면 STEP 2의 GridSearchCV 내부 5-Fold 교차검증에서도 각 Fold의 검증 데이터에는 SMOTE가 적용되지 않습니다.
- 이전 실험(SMOTE를 분할 전 전체 데이터에 적용)에서는 테스트셋 불량 샘플의 97.6%가 학습셋과 근접 중복되는 데이터 누수가 발생했으나, 이번 구조에서는 발생하지 않습니다.

## STEP 2~3 결과: 모델 비교 (Train 내부 5-Fold CV 기준)

| Model | Recall (미탐방지) | Precision (오탐방지) | F1 |
|---|---|---|---|
| **GB_Original (class_weight)** | **0.699** | 0.105 | 0.182 |
| RF_SMOTE | 0.589 | 0.074 | 0.130 |
| RF_Original (class_weight) | 0.571 | 0.089 | 0.153 |
| GB_SMOTE | 0.465 | 0.108 | 0.174 |

→ Recall 최우선 기준으로 **Gradient Boosting + class_weight(`GB_Original`)** 선정. class_weight 기반 방식이 SMOTE 기반보다 이 데이터에서는 더 우수했습니다.

## 최종 결론

Threshold는 통계가 아니라 **현장의 오탐 비용 vs 미탐 비용**으로 결정해야 합니다.

- 불량을 절대 놓치면 안 되는 경우 → **Threshold 0.23** (불량 14건 전부 검출, 대신 오탐 192건)
- 오탐(재검사 비용)을 최소화해야 하는 경우 → **Threshold 0.9** (오탐 4건, 대신 불량 71% 누락)
- 자동차 부품 공급망은 불량 유출 비용이 후공정으로 갈수록 기하급수적으로 커지는 구조라, **0.23~0.4 구간**이 실용적인 절충안으로 판단됩니다. 최종 수치는 팀/현장 합의로 확정 필요합니다.
